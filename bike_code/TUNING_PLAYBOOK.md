# PID 自主调参手册 (给项目内 Claude Code)

> 目标:CC 依据一段扰动日志 + 源码,方法化地迭代 PID 参数(必要时改代码)。
> 模式:Level 1 —— CC 负责"分析→决策→改",人负责物理安全(上支架/系绳、触发每次运行、随时断电)。
> 配套:遥测 v2(日志自带参数)、OLED 菜单(快速注入参数,免烧录)、固件测试扰动(可复现激励)、pid_tuning_bridge.py(算指标)、TUNING_JOURNAL.md(迭代记录)。

## 0. 铁律
- **一次只动一个参数**(或一处代码)。同时动多个 = 无法归因。
- **尊重边界与符号锁**:菜单表里的 min/max 是硬边界;角度环/飞轮速度环增益上界锁死在 0(越 0 会反号、当场翻车)。
- **变差就回滚**:主指标变差、或出现增长型振荡/饱和跑飞/摔倒,立即回到上一组参数。
- **按环顺序**:先内环(角速度)→ 角度环 → 飞轮速度环。外环没稳前不调里层以外的。
- 参数微调走 OLED 菜单(免烧录);只有判断"这不是拧参数能解决、需要加滤波/改环路结构"时才改代码 + 烧录,并说清改了什么、为什么。

## 1. 目标(按优先级)
1. **稳定**:无增长型振荡、无饱和跑飞、不摔。任何一步破坏它 = 立即回滚。
2. **静态**:飞轮空转 now_speed0 均值 ≈ 0;稳态角误差 ≈ 0(主要靠 angular_zero,已整定到 -1.27,每次复查)。
3. **扰动响应**(看测试脉冲那段):在不引发饱和/D 项放大噪声/持续振荡的前提下,**尽量小的超调 + 尽量短的恢复时间**。

## 2. 指标(pid_tuning_bridge.py 从 summary.json 给出)
每窗 summary 必须带:
- `params`:本窗用的 7 个量(av_kp/ki/kd, an_kp/ki/kd(注:内环是 av_*、角度环是 an_*), fw_kp/ki/kd, angular_zero) —— 来自遥测 v2。
- 稳态段:imu_rol std、稳态角误差、now_speed0 均值/漂移、饱和占比、D 项逐帧抖动。
- `step_response`(测试脉冲那段,以 TEST_ACTIVE 上升沿为 t0):**超调**(峰值偏离)、**恢复时间**(|角误差| 回到 ±0.3° 并保持)、**峰值飞轮转速**、恢复期饱和占比、残余稳态偏差。
比较两版参数时:先看"稳定"没被破坏,再比 step_response 的 恢复时间 + 超调,同时 D 抖动/饱和不许变差。

## 3. 每轮迭代循环(Level 1)
1. **人**:车上支架/系绳,进平衡(M0=1);按测试扰动键(固件注入固定角度脉冲);`python3 pid_tuning_bridge.py --port ... --baud 460800 --capture 8`。
2. **CC**:读 logs 里最新 summary.json(参数+指标)+ TUNING_JOURNAL.md + 相关源码。对照目标诊断,决定**一处**改动:给出 参数名、old→new、理由、预测效果。
3. **CC**:把这轮追加进 TUNING_JOURNAL.md(见格式)。
4. **人**:菜单里改这个值(或 CC 改了代码则烧录);**重复完全相同的扰动**;再抓一窗。
5. **CC**:对比前后 —— 留下 or 回滚;给下一步。指标不再改善就换下一环,或收敛结束。

## 4. 各环启发式
- **内环 角速度(av_kp, av_kd)**:先把 kp 往上加到出现轻微高频抖/啸叫的临界,退回约 25%;再加 av_kd 压抖,但盯住 D 逐帧抖动(抖动 >> |D|均值 说明在放大噪声,退 kd 或考虑给微分加低通)。av_ki 通常保持 0。
- **角度环(an_kp, an_kd)**:kp 决定"扶正硬度",加到受扰后开始过冲/来回摆,退回;an_kd 压过冲。an_ki 一般 0,稳态误差交给 angular_zero。
- **飞轮速度环(fw_kp, fw_ki)**:把空转 now_speed0 往 0 拉。太弱→飞轮长期高速空转吃掉余量;太强→和角度环打架、低频晃。以 now_speed0 均值→0 且不引入低频振荡为准。
- **angular_zero**:静态零点,受机械变动影响。每次开工先确认它还让 now_speed0≈0。

## 5. TUNING_JOURNAL.md 迭代记录格式(append-only)
每轮追加一段:
```
## iter <N>  <日期>  focus:<哪个环/参数>
change: <param> <old> -> <new>   (或: code: <一句话>)
before: settle=.. overshoot=.. rms_err=.. fly_peak=.. sat=.. djit=.. idle=..
after : settle=.. overshoot=.. rms_err=.. fly_peak=.. sat=.. djit=.. idle=..
verdict: keep | rollback
note: <一句话为什么>
```

## 6. 什么时候改代码而不是拧参数
当日志显示的是**结构性问题**、拧任何增益都治不好时,才动代码,例如:
- D 项在放大噪声且降 kd 就失去阻尼 → 给微分项加一阶低通;
- 飞轮频繁撞限幅且不是增益能救 → 检查 fly_wheel_rate_limit / 动量管理策略;
- 明显的相位滞后/耦合 → 检查滤波、循环时序、环间连接。
改代码遵循同样铁律:一次一处、能编过、说清动机、可回滚(git)。
